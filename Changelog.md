# 📝 AgriShield Project Changelog
This file automatically tracks all firmware and software changes made to the AgriShield project.

## [2026-07-27] - Firmware Refinements & Connectivity Fixes
- **Button Logic Reverted**: Restored button listener to accept input from both GPIO 25 and GPIO 14. If the button was physically wired to the alternate pin, the system will still detect the page switch perfectly.
- **Continuous Time Tracking**: Modified the OLED header bar (`drawHeaderBar`) to completely decouple the time display from the live Wi-Fi connection. Once the ESP32 fetches the time via NTP during boot, the internal Real-Time Clock (RTC) takes over. The time will now continue ticking accurately on the screen even if Wi-Fi completely drops, until the device loses power.
- **Wi-Fi Failover Acceleration**: Reduced the Wi-Fi reconnection interval from 10 seconds to 5 seconds. Added a hard `WiFi.disconnect(true, true)` flush to prevent the ESP32 from freezing with a `wifi:sta is connecting` error when the router drops the connection.
- **SD Card False-Positive Fix**: Enhanced the `SD.begin()` logic in `setup()` to strictly check `SD.cardType() != CARD_NONE`. This prevents floating SPI pins from tricking the ESP32 into thinking an SD card is mounted when none is present.
- **Hardware Telemetry Integration**: Integrated `<HTTPClient.h>` into `AgriShield_Main.ino` to send live sensor data directly to the backend Python FastAPI server (`/api/v1/iot/telemetry`). Added deep debug serial logging to print out the exact HTTP payload returned by the server if the payload validation fails (e.g., 400 Bad Request).
- **Bluetooth Status in Telemetry**: Added the `bluetooth_connected` field directly to the JSON payload so the frontend dashboard accurately highlights the Bluetooth icon when a phone app is actively connected to the ESP32.
- **BH1750 Dual Address I2C Failover**: Modified the BH1750 `begin()` logic to automatically try both the default `0x23` and alternate `0x5C` I2C addresses. This ensures the light sensor will automatically connect even if you have a module with the ADD pin pulled high.
- **Hardware Connection Documentation**: Expanded `Hardware_Connections.md` to include explicitly detailed wiring instructions for the Analog Sensors, specifically adding safety instructions on how to wire the Battery Voltage Step-Down module to prevent frying the ESP32.
- **Display Ghosting Fixed**: Added a solid black background color parameter `setTextColor(SH110X_WHITE, SH110X_BLACK)` to all rapidly updating OLED text to instantly erase the previous character before drawing the new one, permanently eliminating the ghosting effect.

## [2026-07-31] - Translation Stability & Hardware Analyzer Integration
- **Deterministic AI Translation (`deep-translator`)**: Completely ripped out the NVIDIA Llama-3.1-8B AI translation loop for the Crop Advisor data because the LLM was getting trapped in infinite hallucination loops (repetition collapse) when translating low-resource languages like Telugu. Replaced it with the `deep-translator` library (Google Translate engine) in `predict.py` to guarantee instantaneous, flawless, 100% accurate translations without any token truncation crashes for both Phase 4 (Diagnostic) and Phase 5 (Advisor) screens.
- **`npm run dev` Analyzer Integration**: Patched `package.json` so that running `npm run dev` now seamlessly triggers three concurrent servers: the Frontend (Vite), Backend (Uvicorn), and the Hardware Telemetry Analyzer (`agrishield_analyzer.py`), ensuring all detection and IoT connections are active from a single command.
- **Hardware Log Unbuffering**: Modified `agrishield_analyzer.py` to include `sys.stdout.reconfigure(line_buffering=True)`. This immediately forces the Python stdout buffer to flush, ensuring all hardware monitoring logs are instantaneously visible in the VS Code terminal alongside the Frontend and Backend logs.
- **Path Portability Fix**: Updated the Analyzer launch script in `package.json` to use a relative virtual environment path (`.\.venv\Scripts\python.exe`) rather than a hardcoded DOS 8.3 absolute path, preventing silent launch failures on different computers.
- **GradCAM UI Integration**: Updated the frontend `ScanImageUploader.jsx` and `UploadImagePage.jsx` to natively support the PyTorch `gradcam_base64` payload. Added an interactive "View AI X-Ray" toggle over the image preview that instantly flips the user's uploaded crop image into the Neural Network's heatmap so they can see exactly what the AI focused on.
- **Night Mode Persistence**: Fixed a frontend UI bug in `UI.jsx` where the Dark Mode / Night Mode toggle would forget the user's preference upon page reload. Modified the `useState` initializer for `isDarkMode` to lazily evaluate and restore the user's saved 'theme' preference directly from browser `localStorage`.
